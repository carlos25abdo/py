البرمجة الكائنية (OOP) - هندسة البرمجيات

عندما تكبر البرامج وتصبح معقدة (مثل الألعاب أو أنظمة البنوك)، تصبح الدوال والمتغيرات العادية غير كافية ويصبح الكود فوضوياً. هنا ننتقل إلى مرحلة الاحتراف: البرمجة الكائنية الموجهة (Object-Oriented Programming).
الفكرة ببساطة هي: تمثيل وبرمجة الأشياء الحقيقية كـ (كائنات) داخل الكود!

مفهوم الفئة (Class) والكائن (Object)

تخيل أنك مهندس سيارات. هل ستقوم ببناء كل سيارة من الصفر بوضع العجلات والمحرك بطريقة عشوائية؟ بالطبع لا! ستقوم برسم (مخطط هندسي - Blueprint) واحد يحدد أن كل سيارة يجب أن يكون لها 4 عجلات ومحرك ولون.
- الفئة (Class): هي هذا المخطط الهندسي.
- الكائن (Object): هو السيارة الحقيقية التي صنعتها بناءً على هذا المخطط (يمكنك صناعة آلاف السيارات المختلفة باللون من نفس المخطط).

كيف نترجم ذلك لبايثون؟

# 1. تصميم المخطط (الكلاس)
class Car:
    # دالة التهيئة: وظيفتها استقبال المواصفات عند التصنيع
    def __init__(self, brand, color):
        self.brand = brand  # صفة الماركة
        self.color = color  # صفة اللون
        
    # يمكن للسيارة القيام بأفعال (Methods)
    def start_engine(self):
        print(f"السيارة {self.brand} اشتغلت! فرررم")

# 2. إنشاء السيارات (الكائنات) من المخطط
car1 = Car("تويوتا", "أبيض")
car2 = Car("فيراري", "أحمر")

# 3. التفاعل مع الكائنات
print(car1.brand)    # سيطبع تويوتا
car2.start_engine()  # سيطبع السيارة فيراري اشتغلت!

الأسرار المهنية:

  • دائماً تبدأ أسماء الفئات class بحرف كبير (مثل Car وليس car).
  • كلمة self تعني (نفسي). تستخدم لكي يربط الكائن الصفات بنفسه فقط ولا يخلطها مع كائنات أخرى.
  • الدالة __init__ (بشرطتين سفليتين قبل وبعد) تسمى Constructor وتتنفذ تلقائياً عند ولادة الكائن.

تمرين عملي 🚀

لدينا قالب يسمى Dog يحتوي على دالة bark().

  1. قم بإنشاء نسخة (Object) من هذا القالب واسمها my_dog عن طريق مناداة Dog().
  2. اجعل الكلب ينبح باستدعاء الدالة الخاصة به my_dog.bark().
محرر بايثون
class Dog: def bark(self): print("هوو هوو!") # قم بإنشاء my_dog هنا واستدعاء الدالة
